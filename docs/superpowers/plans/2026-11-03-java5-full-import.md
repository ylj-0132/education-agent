# Java_5全量入库与画像执行计划

**Goal:** 250条原始记录写入本地SQLite；仅200条train生成5个完整画像，接入既有工作台展示。

**Architecture:** 新建批量CLI，复用load_records、CachedChatClient、RunStore和run_profile。每学生一个独立检查点，完整画像才登记到数据库；保留既有JSON供工作台读取。旧小样本入口和.env上限保持不变，全量入口要求显式批量调用预算。

**Tech Stack:** Python标准库、SQLite、现有工作台。

## 约束

- 用户已确认全量原始入库与训练画像，不包含测试分析、推荐出题、Java执行。
- 数据集来源哈希必须与已核查manifest一致；按学生隔离。desc/error_desc只存档。
- 每学生40条train，31个候选知识点，最多71个逻辑请求、142次含重试的请求；五人总硬上限710。实际费用未知，不把调用上限当金额上限。
- 新任务的明确预算不能改变旧任务额度；恢复仍绑定实现、输入、模型与预算。
- 遇到不完整、账户错误或未知远端结果停止后续学生，不创建替代任务重试。
