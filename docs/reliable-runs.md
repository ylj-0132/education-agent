# 任务恢复与排查

当前使用Python自带SQLite保存任务状态。Java_5全量入口另外使用本批`dataset.sqlite3`保存原始证据、完整画像版本及本批学生画像指针；它与任务检查点分开，不是多用户数据库服务。当前画像提示词版本为embracing-adapted-v4-execution-evidence；模型分工、输入和实现哈希均绑定任务，旧任务不绕过版本校验恢复。

## 启动和恢复

在项目目录执行。新任务仍需显式 `--execute`，输出目录必须不存在。

```powershell
python run_profile.py --execute --output runs/my-run --max-calls 10
python run_profile.py --status --output runs/my-run
python run_profile.py --trace --output runs/my-run
python run_profile.py --execute --resume --output runs/my-run --max-calls 10
```

首次指定过records、concepts、student等参数的，恢复时仍需指定相同参数。输入内容、知识点配置、模型、端点、输出上限、超时、提示词及实现文件哈希必须一致。预算在首次运行时固定，恢复不能增加或重置；密钥不写入身份记录。

`--status` 和 `--trace` 不读取密钥、不访问网络，可在进程被强制结束后使用。--trace输出包含学习证据与模型返回内容，仅应本地查看。进程崩溃时状态可能仍显示running，应结合最后的事件和步骤判断；恢复时会将未结束的步骤标记为中断、无响应请求标记为unknown。

## 文件与状态

- `checkpoint.sqlite3`：权威记录，每次状态转换与对应事件在同一事务提交；包含任务ID、步骤、请求次数、原始请求/响应及验证后的步骤结果。
- `trace.json`：正常收尾或可捕获异常后的可读快照。强制退出时可能过期或不存在，改用 `--trace` 直接读取SQLite。
- `run.json`：任务摘要，同样只是导出快照。
- `partial-profile.json`：仅部分完成，不代表完整画像。
- `profile.json`：所有提取和涉及的知识点汇总都完成才生成；完成仍不等于内容已经人工核验。

每条trace有任务ID、步骤ID、时间与事件类型；步骤关联record_id/problem_id或concept_id。请求记录尝试编号、哈希、持续时间、返回ID及服务端提供的请求编号、usage、异常类型/原因/堆栈位置。当前密钥文本会脱敏，不保存认证头或堆栈局部变量。

## 恢复规则

1. 成功且通过业务校验的步骤直接读取检查点，不依赖全局缓存。缓存仍可用于旧结果复用。
2. 响应已落盘但未完成校验时，重新解析已保存的响应，不重发请求。
3. 发送记录已落盘但响应未知时，不自动重发。预留次数仍占预算，费用未知；需核对供应商记录后再明确决定是否开启新任务。
4. 同一步骤同一请求整个任务最多两次尝试。失败后重启不会再获得两次机会；账户、权限、参数或HTTP429错误阻止后续新请求。
5. 独立知识点汇总失败后继续其他知识点。提取阶段缺少任何作答结果时不开始汇总，防止悄悄忽略一部分历史证据。
6. 同一任务使用操作系统锁，重复启动会被拒绝；进程退出会释放锁。检查点事务与结果文件原子替换减少写一半的风险。

本机制不能保证远端恰好执行一次：请求超时或本机中断前，供应商可能已经执行并计费。SQLite检查点用于本机单进程恢复，不支持多台机器通过同步盘并发写同一个任务；硬件损坏、云同步冲突和供应商内部故障不在本轮测试覆盖内。

## 验证与异常处理

最后完整离线验证142项通过（2026-10-30）。测试覆盖进程退出、收到响应后中断、缓存与业务校验、预算、锁、CLI及恢复；不是生产环境所有故障的保证。付费实验及恢复结果见原实验记录。

接口与检查点共用retry_policy.py；SSLEOFError及其URLError包装允许限额内补试，证书验证失败和其他协议/配置错误停止。明显服务拒答与普通证据不足分开，检测不能覆盖所有表达或代替内容审阅。

## 业务校验与缓存隔离

StudentProfile调用项目客户端的complete_validated入口，把允许的知识点ID、禁止重复等业务校验传到缓存提交前执行。普通两参数回调仍由画像模块本地校验；自定义带缓存的适配器也需提供相应验证入口，不能只返回未经业务验证的缓存结果。

网络新响应、旧缓存、崩溃后保存的原响应重放均执行结构和业务校验。不存在的知识点、重复知识点或格式不合格响应不进入成功缓存；旧无效缓存原文件移至failures目录，trace记录cache_rejected、原因和文件位置。新响应失败诊断保留原请求、原响应及business_validation原因。收到响应后才发现业务错误时，请求在检查点标为rejected，不能作为成功结果恢复。

允许按既定上限补试一次，拒绝结果与历史尝试继续占预算，恢复不重置。中文正常内容、Unknown及合法空观察列表仍可接受。实际模型、步骤与原响应以检查点为准；改变stage_models或使用记录快照不得作为同一任务恢复。
