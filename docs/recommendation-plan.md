## 核心对象与约束

`prepare_context`按学生、教师范围及相关知识点组织画像、原始证据、条件关系和可选使用记录。新目录概念没有观察即为未知，旧定义改变需显式迁移；partial画像不得冒充完整画像。

`build_generation_request`携带目标、理由、证据、教师要求、关系及相关历史；来源区分explicit_selection和model_direct。正式B交接绑定推荐任务，出题时从权威记录重建核验，不能仅凭交接文件存在就执行。

推荐关系完整匹配则保留；只连接部分目标列待核对辅助关系；不存在或无关引用排除并记录。关系审查不增加目标、不传播掌握，不因辅助关系拒绝整个推荐。

生成题保存question_id、版本、哈希、题面、答案与审核。接收记录绑定准确版本，真实作答与test_fixture分开。原始观测、工具结果和模型推断分别保存；模型所用信息不包含外部desc/error_desc。

运行输入压缩为全通过摘要或失败输入、预期/实际输出和数量，完整日志可回查。历史清单可以显示已接收但未入画像的提交，不能自行把它写成掌握状态。正式模型选择和使用记录都纳入恢复身份，修改后必须新任务。

## Java出题检查规范 2026-10-28

以下标准仍适用；生成与审核已实现，轻量Java验证另行批准执行。AI审核不当作专家真值，题目使用标签不证明学生掌握。

### 核心维度与判定依据

| 检查项 | 检查内容与通过依据 | 未通过或证据不足时 |
| --- | --- | --- |
| 题意清晰完整 | 题干、输入输出、合法输入范围、边界条件和样例相互一致；审阅者指出具体位置，而非仅写“清晰”。 | 缺失或矛盾可定位时要求修订；多种解释不能排除时待复核。 |
| 可解性与答案正确性 | 解法符合题意；Java代码在逐份审阅批准的轻量环境编译运行，样例和针对性边界测试符合独立推导的预期。保存环境版本、命令、退出码、输出和测试依据。 | 明确反例或编译错误要求修订；未执行、环境不可用或预期结果未核实时待复核，不能写成题目错误或验证通过。 |
| 知识目标匹配 | 检查题目是否提供目标知识点的合理练习机会，将目标映射到题目要求或合理解法中的具体操作；核对教师范围和明确的方法要求。允许其他正确解法，不要求目标知识点不可替代。 | 明确目标或方法要求未落实、越界时要求修订；依据不足时待复核。不能仅因存在替代解法判失败。 |
| 难度与学生适配 | 说明所需前置知识、推理步骤、实现负担及与教师要求、相关画像证据的关系。无观察不等于不会，模型判断不当成校准难度。 | 明显违反要求则修订；缺少画像或可靠难度依据时标待复核，仍可保存为诊断候选，不能声称个性化适配已确认。 |
| 解析质量 | 思路、关键步骤、参考代码与样例一致；解释为何可行及边界处理，不只重复答案。 | 能定位的错误或解释缺失要求修订；无法确认的推导待复核。 |
| 组合合理性 | 多目标任务逐项说明各知识点在解法中的用途和联系，防止宽细标签重复计数或生硬拼接。 | 不合理时调整题目或反馈需要拆题，不静默删改推荐目标。单知识点任务可标不适用，不扣分。 |

答案正确不要求Java实现唯一。题目允许多种合法输出时，需要明确判定规则，不按单个字符串误拒。测试通过只表示已覆盖用例通过，不是完整正确性证明；生成代码与同轮生成的测试答案相符不能单独作为正确证据。关键预期结果应独立推导，适合时使用小规模穷举或另一种简单解法交叉验证。核验与生成使用同一模型时仍可能同错，应保留该限制。

### 输出与流程约定

- 每项保存维度ID、pass/fail/uncertain/not_applicable、理由、题目或证据定位、检查方式、模型或工具版本。not_applicable只能用于确实不适用的项目并给理由，不能替代缺失检查。
- 先程序核对字段与范围，再进行内容审阅和轻量代码验证；模型可一次返回多个维度，不要求每维一个智能体或一次API调用。
- 任一适用核心项fail时需要修订；无fail但有uncertain时标needs_review；所有适用核心项均pass才标检查通过。代码尚未执行时不得标全部检查通过。通过表示满足当前检查，不保证全域正确或学习有效。
- 网络失败、服务拒答、超时和审核JSON无效属于执行失败，不充当题目质量评分。修改后检查绑定新的题目版本，旧审核和运行结果不得套用到新版本。
- 多样性、趣味性、创造性作为补充观察，不抵消正确性失败。多样性需有比较集合；一题不能直接宣称多样性好。
- 两类入口保持：B成功推荐交接，以及教师或学生直接提出要求。题目、答案、检查、修订历史关联请求和推荐ID；生成与检查结果不更新学生画像。执行器沿用已有trace、检查点和预算机制。
- 当前实现生成一道候选，最多一次内容修订，初稿及审核正常2次请求，含修订最多4个逻辑调用。达到预算后保留失败或待复核状态；Java另行逐份批准执行。

### 少量样例与检查器复核

开发阶段抽查生成题，并准备少量可确认缺陷的测试题（题干矛盾、错误答案、编译错误、目标缺失、解析冲突），检查是否漏检；同时保留正确题检查误拒。手工构造案例与实际生成样本分别报告。无独立人工标签时只报告确定反例、测试结果和AI辅助审阅，不称专家评价或正式准确率；将来有独立标签再统计错题放行和好题误拒。不能将检查器自身判断用作真值评价它自己。

## 投稿方向讨论 2026-10-30

用户希望在2026年12月前投稿，并已授权本地前端与显式任务启动。本节是候选研究方案，不代表创新性或效果已验证，也不授权新增付费实验或学生程序执行。

当前明显不足在于研究证据：已有小样本主要用于开发和排错，不能同时当作独立测试集；E036历史比较混有版本变化，E037只有单学生三题；尚无独立的知识点归因标签、推荐适切性标签或审核漏错误拒统计。142项工程测试证明程序约束，不证明模型判断准确。前端增强可展示性，不单独构成算法贡献。

### 与现有研究的边界

- [Embracing Imperfection](https://arxiv.org/abs/2505.19997)已有从历史记录构建认知画像的思路，项目不能把“画像+证据检索”直接称为首创。
- [CBEGRec作者仓库](https://github.com/sosweetzhang/CBEGRec)已有目标概念组合与练习生成；本项目采用B是工程与阶段选型，现有实验不足以证明方法总体优越。
- [EduAgentQG](https://arxiv.org/abs/2511.11635)已有规划、出题、审核和修订；六维审核和闭环本身不足以支持新颖性主张。
- [编程反馈课堂研究，PMLR 2026](https://proceedings.mlr.press/v339/heickal26a.html)已比较自然语言提示、失败用例反馈和无AI反馈。因此仅加入运行信息也不能直接宣布创新。该研究针对反馈与课堂表现，本项目可进一步调查“证据表达如何影响知识点归因及下游推荐”，这仍是待查新的候选切入点。

### 优先候选：面向画像与目标推荐的运行证据表达

研究问题：在保持模型、题目、代码、测试集合和提示规则相同的情况下，精简但保留结果语义的运行证据，能否减少不受支持的知识点归因，并以更少上下文保留对后续目标推荐有用的信息？具体机制为区分未执行、失败、通过及未知，绑定原始提交，成功仅数量摘要、失败保留反例与计数，禁止把通过提升为掌握。现有实现是起点，尚不能称为新的算法或已获验证的贡献。

建议实验分三组：题干+代码；题干+代码+完整运行记录；题干+代码+精简运行记录。同一模型同一参数，使用相同已有独立用例结果，不把模型切换与输入改变混成一个变量。重复请求数与预算先确定；缓存复用不算独立重复。优先在作答提取阶段对照，只有归因差异稳定时才在有限案例上检查推荐影响，避免反复跑整条付费流程。

标注先于看模型结果：对每份提交列出可确认程序事实、实际反例、允许的知识点归因、证据不足项；由独立审阅者盲评，报告分歧。可报告错误事实比例、无依据负面归因、同一根因重复计入知识点、关键问题漏检及输入tokens；指标须先固定分母。没有独立标签只能报告案例，不能标成正式准确率。摘要与完整记录的成本比较不能忽略运行及人工核验成本。

样本应覆盖其他学生与不同错误类型，排除长期提示调试的三题作为主测试依据。训练/测试划分保留，正式评测须先冻结方案并核查跨学生共享题造成的泄漏；不能为证明结论挑选有利案例。只有五名学生时报告学生层面的分组结果和不确定性，不能把多次请求当作更多学生。

### 备选与停止条件

若以上差异不稳定，改为真实报告“运行事实仍不足以保证知识归因”的实证研究或系统演示，而不继续堆角色、评分或自评。证据追溯、增量更新和可恢复工作流可作为系统贡献；它们是否足以支持目标刊会，需要在选定投稿类型后重新判断。旧推断纠错仍暂缓，若以后作为方法创新，须单独讨论范围。
